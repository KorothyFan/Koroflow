# KoroFlow 制作与发布管理

将同一作品的制作、交付、统计和发布关联起来。先读本地配置和本次涉及的源记录；不要把本技能的安装或配置当成生成、上传、发布或定时任务授权。用户已有授权支持的步骤继续执行，不重复索要确认。

## 配置与入口

本技能的 `scripts/operations.py` 是自包含Python 3.11+标准库工具。命令输出JSON；除 `init` 创建新配置外，均只读本地文件，不连接平台、不占用视频、不刷新表格。

配置从用户明确指定的 `--config` 或 `KORO_OPERATIONS_CONFIG` 读取；由仓库安装时可读 `references/local-setup.json` 获取本机配置路径。没有配置时按 [安装与配置](references/setup.md) 创建本地配置，先定位用户现有目录。不得因配置缺失重新制作或迁移历史工程。

```text
python -X utf8 <本技能>/scripts/operations.py doctor --config <本地配置>
python -X utf8 <本技能>/scripts/operations.py check --config <本地配置>
python -X utf8 <本技能>/scripts/operations.py accounts --config <本地配置>
python -X utf8 <本技能>/scripts/operations.py snapshot --config <本地配置> --date YYYY-MM-DD
python -X utf8 <本技能>/scripts/operations.py plan --config <本地配置> --request <发布请求.json>
```

`check --hash`额外核对已选交付文件的SHA256。退出码0表示本地检查无错误，1表示记录存在错误，2表示配置/调用失败；不代表主观成片质量、平台登录或真实发布通过。

## 按任务读取

- **制作、继续、修订**：读配置指向的制片约定、创作偏好和项目BRIEF/TREATMENT/PROGRESS。调用已安装 `hypit-haiyi` 或用户选择的制作能力；缺少能力时说明具体依赖。沿用角色比例、声音身份、完整叫声和原片剧情约束，检查实际画面和声音后记录交付。付费范围遵循已有委托，不自动扩大重试次数。
- **整理、交付、统计**：读 [作品与统计](references/records.md)。使用真实work_id和已选版本；先check，再按现有刷新入口执行用户要求的刷新/打包。snapshot只是已有汇总，必须报更新时间，过时或缺失时不编造新数字。
- **挑片、发布、预约、回填**：读 [发布与恢复](references/publication.md)。用本地账号清单找完整身份，整理具体发布请求后运行plan；通过只表示可进入真实执行核对。第一版没有云机/浏览器执行器，实际执行须通过当前环境已经可用的连接或UI能力，缺失时保留计划并准确说明。

## 跨任务不变量

- 修订沿用work_id；按生成任务ID统计成功生成，按作品去重交付，明确采用/发布证据才计采用。
- 制作目标配置与发布账号配置分开，账号失效或本次只发一条不自动更改制作目标。
- Excel手填字段按稳定记录编号保留，不按行号回填，不覆盖未保存输入。文件夹预标记、人工标记、预约确认和平台发布证据分别保留依据。
- 目录与硬链接只提供分类入口，不证明生成、交付、采用或发布。历史保留成片不强行补制作日期或恢复旧工程。
- 多聊天追加各自事件，统一刷新程序负责汇总；不要同时手改总表。
- 依赖、接口地址和账号状态以本机配置及本次观察为准。凭据从本地授权存储/环境读取，不输出到记录、仓库或分发包。

用户当次明确要求优先于默认配置。创作偏好、账号、标签和临时排期属于本地配置，不写死为所有安装者的规则。
