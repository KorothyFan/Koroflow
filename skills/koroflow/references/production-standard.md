# KoroFlow 视频制作规范（完整版）

版本：2026-10-22。适用：参考复刻、角色替换、原创短片、图片资产与视频制作、修订、验收和交付。可供人工制片或 AI 助手使用。

本规范规定制作行为；模型能力、参数、价格、额度与连接状态须在实际执行时核实。文中的审批是操作者遵守的流程，当前代码并未实现统一的预算审批弹窗或所有执行路径的自动费用拦截。核心的文件指纹、任务状态与质量门槛不等于自动审片。

## 1. 开始前：恢复要求与项目状态

- 优先级：用户本次明确要求 → 最新明确采用的项目方案与角色资产 → 本地创作偏好 → 本规范的通用默认。历史偏好冲突时标出已被覆盖的条款，不能同时塞入提示词。
- 先读取已有的 BRIEF.md、TREATMENT.md、PROGRESS.md、正式提示词、任务回执和版本记录，再继续制作。已有作品沿用 work_id，不因换聊天、改名或换平台重新计作新作品。
- 新项目先明确：参考来源、成片数量、主配角映射、保留与替换项、画风、画幅、时长、声音、交付方式及可用预算。只补问影响制作的缺失信息。
- 用户只让找素材、看视频、分析剧情、写提示词、估算或修改方案时，只做这些工作。安装工具、配置账号和同步规范不构成付费生成授权。
- 不凭视频封面、自动标题或转写结果编造剧情。看不到或听不到的内容明确标为未核实。

## 2. 参考片分析与三种制作路径

### 路径 A：原视频参考／编辑

先实际看完整参考片，记录关键动作、因果顺序、镜头关系、表情变化和笑点。核实平台是否支持所需的视频编辑、参考或动作迁移能力；“能上传视频”不等于“能够逐帧严格复刻”。

原视频负责剧情、动作和节奏，角色图负责目标身份、服装、比例和材质。采用用户要求的严格程度。用户希望“严格按原版动作，不用逐个描写”时，保留清晰的复刻指令与必要的替换、声音、接触和结尾约束，避免另一份详细脚本与原视频争夺动作控制。

### 路径 B：解读复写

适用于用户选择不上传参考视频，或原片水印、音轨、风格等不适合直接进入请求的情况。先看懂原片，再将可见剧情、镜头和动作关系写成独立方案，只上传本项目需要的角色、道具和场景资产。

明确说明这是基于解读的重建，不能声称与原片帧级一致。原片、带水印截图与原声是否上传，逐项列入提交前确认单，不默认沿用。

### 路径 C：2D／其他参考 → 3D场景图 → 视频

1. 从参考中提取角色站位、机位、景别、透视、家具与道具关系、光线和剧情所需空间。
2. 用已采用角色资产和布局描述生成立体场景图；必要时为不同空间／镜头准备多个场景资产。2D风格本身不意味着剧情更差，也不意味着必须转换。
3. 检查角色身份与比例、立体材质、写实环境、接触阴影、道具数量、站位和动作活动空间，确认没有把三视图变成多名角色。
4. 以核准场景图作为视觉参考，再由提示词或经过确认的动作参考驱动视频。明确图片是身份／场景参考还是字面意义的首尾帧。
5. 一张场景图可以锁定外观和空间，不能单独保证后续动作、因果、时序或声音一致。长剧情应核对模型时长与连续性能力，必要时分段制作。

场景图与视频是不同的付费请求，消耗须合并告知；若场景图失败、偏离方案或改图超过授权范围，先处理确认，不能不断试到满意。

## 3. 角色、环境和表演

- 身份以当前采用资产为准。保留头身比、短胖轮廓、四肢长度、服装和标志特征；不为填满原角色轮廓而拉高、拉长或增加肢体。
- 三视图中的正侧背是同一角色的不同方向，成片人数由剧情决定。参考图的表情与姿态不锁死后续表演。
- 本项目默认“立体Q版角色＋相对写实生活环境”：真实尺度、可信材质、自然光、透视、接触阴影和现实代入感。其他使用者可在 Brief 中替换风格；不能把默认当作所有用户的要求。
- 表情围绕剧情设计，可使用期待、得意、心虚、尴尬、机灵、装可怜、生气、惊讶、满足等变化；不把所有冲突统一写成受惊大哭。
- 动作要有准备、发力、重心移动、接触、缓冲和收尾；碰撞、捏脸、抓取、递交、跳跃后要有合理撤手与恢复，避免手或道具粘住角色。
- 先确保时间容得下动作。动作僵硬时可先适当延长时长、减少冲突指令、强调连续动作与自然接续，保留用户认可的剧情，避免无故大改。
- 多角色明确谁先动、谁反应、视线对象和前后遮挡；不交换身份或凭空增减角色。舞蹈可以在用户允许的时段让模型自由发挥，同时维持角色比例、自然重心、连续节奏与生动表情。

## 4. 声音、语言与画内文字

- 默认无字幕、画内标题、水印、平台 UI 和可识别中文标识。品牌、包装、屏幕与招牌也要检查。英文发布标题和标签放在交付文案，不能自动烧进画面。
- “纯净画面”不自动等于静音：分别确认生成音频、环境／动作声、角色发声、对白、配乐五项。
- 默认不加配乐、歌曲、旁白；角色若有固定叫声，不能擅自改成人类对白。主人等其他角色确需台词时，按用户批准的角色分配和英文台词执行。
- 逐角色区分声音身份、正式发声词与表演风格。取消音色参考只删除参考附件与相关描述，保留用户认可的清脆软萌、自然呼吸、情绪变化等声音要求。
- 近景声音亲近而不刺耳，远景、玻璃、遮挡和室内外声场与空间一致；保留必要的手部接触、布料、脚步、食物及环境声。
- 有声回合在真实嘴部表演：起音张嘴、连续音节自然开合、停声后收口。嘴被遮挡、背面或嘴里有食物时，不为展示口型强加叫声或新增镜头。
- 优先同次原生音画生成。另配音、变调、变速、混音、去字、插帧和剪辑都要单列；不能把本地处理版称作平台原生版。

## 5. 提交前必须核对：方案、参数与消耗

这是付费提交前的正式检查点，适用于视频、场景图、角色图、配音、音乐、增强、去字、小样和重试。先完成可逆的准备、文件检查与询价，再把具体请求交给用户核对。确认单可一次覆盖整批及明确的依赖阶段。

### 5.1 提供给用户的确认单

| 类别 | 必须展示的内容 |
| --- | --- |
| 本次产出 | 作品与版本、角色组合、预计独立成片数、图片／视频／其他请求数、各阶段依赖与并发安排 |
| 制作方案 | 来源与已核实剧情、选择的制作路径、保留项、替换项、关键表情／动作、结尾变化、完整正式提示词或可直接打开的文件 |
| 参考附件 | 逐项列明实际准备上传的文件与职责；角色资产版本、原片是否上传、音色参考是否启用、场景图是否只作参考或作为首帧 |
| 平台与扣费来源 | 实际平台、所用账号／额度来源的可识别说明；使用网页登录额度还是指定 API 计费来源，不展示密钥，不假定二者额度共用 |
| 精确模型 | 平台实际模型名称／ID、版本和质量／速度／价格档位。相同720p的不同档位须分清，不能仅写“720p模型” |
| 输出参数 | 生成模式、时长、画幅、分辨率、数量、是否生成音频；可设置的帧率、种子、参考强度等。接口未提供的写“平台自适应／不可指定” |
| 输入与特殊开关 | 文件格式、编码、尺寸、时长、素材数量和上限；参考视频自适应要求；有真人素材时按平台实际定义核对对应开关，不机械一律开启 |
| 预计消耗 | 计费单位、报价来源与查询时间、每项单价／预估、计价依据、批量合计、已成功可复用项、不确定项和预算上限 |
| 余额与可承受量 | 能实际读取时报告余额、查询时间和按当前报价可做的大致数量；读不到写“余额未核实”。不同额度池、套餐与有效期不擅自合并 |
| 授权边界 | 本次允许提交哪些请求、最多几次、最大总消耗、是否含小样／备选／重试，以及哪些变动需重新核对 |

模板见仓库 `templates/production-confirmation.md`。给非技术用户时使用可读字段，不仅贴 API JSON。参数与附件必须能对应到实际提交请求。

### 5.2 价格、额度和授权规则

- 提交前查询与本次模型、档位、输出参数、参考输入和扣费来源对应的实时价格。有低价档与高价档时展示可用差异，按用户选择执行；用户要求先低价试作时不能悄悄升档。
- 区分单条消耗与整批总消耗。参考视频时长、输出时长、数量、分辨率、声音或其他因子是否计价，以平台当前规则为准，不能套用另一个模型的计费方式。
- 平台积分、额度、credits等保留原单位，不无依据换算人民币。余额、预计扣费、已确认实际扣费分开记录；错误返回中的空费用不证明免费、退款或未扣费。
- 不能报价时明确未知部分和计费风险；没有既有明确预算授权时，等用户接受具体上限／范围后再提交，不以旧价格冒充实时结果。
- 用户核对后说“就按这个生成／提交”可视为对该确认单范围的授权。批量授权持续覆盖已列明的请求和阶段，无须每个镜头再次询问。
- 已明确授权且参数、附件、数量与预算均在范围内时继续执行。“先不生成／先给我看”则必须停在确认单，不提交。
- 换模型、升价档、提高分辨率、增加时长／数量、增加付费步骤、切换扣费来源、实质改剧情或超预算时，先更新变更与总消耗；未被原授权覆盖的部分再次确认。
- 未授权的付费重试不自动执行。用户已批准的有限重试可按原范围继续；每次记录原因、差异与剩余额度。不能把“调整参数”或“技术修复”当成免费重试。

### 5.3 提交前的最后核验

核对最终提示词版本、附件版本与请求指纹、角色人数、模式兼容性、输出参数、实时价格和授权一致。消除提示词之间的冲突，例如“无对白”又要求台词、“保持立体”又引用平面赛璐珞风格。

海艺/Hypit路径先执行适合本次请求的 info、check、plan、pricing，必要时 doctor。它们不提交媒体生成，但部分命令会读取远端状态／价格；其他平台使用实际存在的对应预检工具。预检通过不证明生成质量。只有确认授权覆盖后才调用 build 或平台真实提交接口。

## 6. 提交、等待、失败与取消

- 每个请求在授权范围内提交一次，立即保存请求摘要、提交时间、远程任务 ID 与回执。工具轮询结束、网络超时或等待窗口关闭不等于任务停止。
- 未知结果先查原任务和提交回执；不能为了“继续等待”再提交一次，不能换任务键规避查重。
- 状态明确区分：准备、已提交、排队／运行、成功、失败、结果未知、暂停／取消请求与已确认取消。用户取消后停止后续提交；已运行任务尝试使用平台真实取消能力，不虚构已退费。
- 失败保留错误原文、原任务状态、已成功素材和计费证据。可先做本地修正和离线校验，付费重提按第5节授权规则执行。
- 成功素材如需复用，在新请求／Run中明确绑定；不能仅因本地有缓存就保证不会重复付费。
- 并发按用户接受的批次数、平台限制和依赖关系安排；场景图未通过前不能把它当已核准资产批量推进。不得擅自另开聊天或让其他聊天提交任务。

## 7. 实际审片与修订

完整查看真实最终文件；含音轨的版本须实际听审。抽帧、编码探测、ASR和静音检测只是辅助，不能单独证明动作流畅、声音可爱或口型同步。

| 检查项 | 验收内容 |
| --- | --- |
| 剧情与镜头 | 关键动作、因果、角色位置、视线、机位／景别、表情转折、笑点与结尾符合本版方案 |
| 角色与风格 | 身份、人数、头身比、四肢、服装、材质稳定；立体Q版没有退回平面2D；环境有现实感 |
| 动作与接触 | 无明显僵硬、滑步、跳帧、穿模、多余肢体；抓取、撤手、落地、恢复等关键动作完整 |
| 表情 | 情绪有前后变化；按剧情表现，避免全程固定微笑或所有反应都哭 |
| 声音 | 正式叫声／台词、音色、情绪、自然停顿、动作声和空间关系符合要求；检查意外人话、配乐与旁白 |
| 口型 | 实际听看发声开始、嘴部连续开合和停声收口；不以一张开口帧证明同步 |
| 画面洁净度 | 无未授权字幕、中文标识、画内标题、水印、平台UI及原角色残留 |
| 文件技术 | 可播放、完整时长、实际宽高／分辨率、编码、帧率与音轨；保留原文件及SHA256 |

每项记录通过、未通过、未检查／无法核实及证据。没听过不能写“音频通过”，没看全不能写“整体动作验收通过”。用户明确接受某项偏差时记录具体豁免及本版范围，不把一次接受变成永久放宽标准。

平台成功只是“成功生成”；未通过必检项的先作为候选给用户看，不宣称正式合格交付。修订先解释问题、最小必要改法、参数变化和预计消耗，再按已有授权或新确认执行。旧版保留，修订沿用作品编号。

## 8. 项目、版本与交付

建议结构如下；已有工程沿用原结构，不为统一形式大搬迁：

```text
角色_具体剧情_YYYY-MM-DD/
  BRIEF.md                  目标、来源、映射、预算与授权
  TREATMENT.md              剧情、镜头、表演和声音方案
  PROGRESS.md               真实任务、审片、剩余问题和交付状态
  项目文件/
    提交确认单/              提示词、参数、报价与授权依据
    任务记录/                请求摘要、回执和远程任务ID
    统计事件/                各聊天追加的独立JSON事件
    发布信息.json            work_id、角色、剧情、英文标题与标签
  生成素材/                  原生输出与采用资产的版本映射
  成片输出/                  原生版、修订版、本地处理版分开命名
```

- 平台 URL／VID记录在 Brief，具体剧情作为主要查找名。公共资产与工程分开，原资产不覆盖，当前采用版本有明确指向。
- 交付注明：剧情与角色、版本、实际任务状态、原生还是后期、真实文件路径、时长与尺寸、审片结果和未解决问题。
- 保留平台原生输出。用户要求桌面打包时复制并校验SHA256，工程原件保留。修订不覆盖唯一原片；硬链接不是独立备份，修改视频应另存。
- 每个作品准备一个可直接发布的英文标题和相关hashtags，文案与视频分开。标签若声称“平台常用／流行”，需实际证据；建议词与已核实使用词分清，不编造播放量。
- 工具内部标签、source／回合编号用于映射素材和台词，不进入字幕或角色发声。正式提示词写清它们的含义，非必要不把工程术语塞进表演指令。

## 9. 统计、库存与发布边界

- 成功生成：按真实成功视频任务 ID 去重；重生成另计。图片、音频、失败任务、本地剪辑与重复导出不算新的视频生成。
- 去重交付：同一剧情同一角色的原生版、配音版、去字版、修订版共用work_id，只计一个独立作品；不同角色独立版本分别计数，多角色同一支视频不按出场人数拆条。
- 确认采用：需要用户明确采用或按本地规则认可的发布反馈；候选可看、声音参考认可、文件存在和文件夹名不能自行证明整片采用。
- 生成归真实成功日；交付与采用沿用作品首次交付日，发布日另记。时区在项目中明确；历史日期不明留空，不根据文件修改时间猜测。
- 新制作、交付、采用、暂停和取消写真实独立事件；并行聊天只追加自己的记录，不同时手改总表。刷新按稳定work_id关联，保留人工字段。
- 每日目标、账号分配、日期覆盖、周末要求和定时任务保存在使用者本地配置。本规范不写死账号、条数或定时任务，也不因阅读／安装而创建自动化。
- 当天新产出是否达标、库存够不够发布分开计算；某角色超额不抵另一角色缺口，修订不重复计算。用户自行剪好并确认完成／发布的按当地规则入账并保留依据。
