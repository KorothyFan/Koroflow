# 从方案到 HTML 审片的协作规范

更新：2026-11-12。配合 [参考复刻执行流程](reference-production-runbook.md) 使用。本页规定操作者实际交付的成果，不代表程序已自动读片、生成网页或完成验收。角色、资产、费用与本机路径由私人配置和当前任务提供。

## 1. 完整链路与适用方式

用户要求或本地偏好启用 HTML 协作时，执行：**实际读片 → 每版职责与元素映射 → HTML 方案 → 必要资产及核对 → 正式请求预检与真实提交 → HTML 原片/成片审片 → 指定项定向修订 → 当前版本与文件交付。** 不把“已提交”当作制作体验的终点。

只要求文字、分析或其他格式时以当次要求为准。不新增逐阶段审批；已授权制作在必要预检后继续，页面用于可见、可核对的协作。原任务结果未知先查原任务，付费重试和扩量遵循已有授权边界。

可复制 [方案与审片空模板](../assets/templates/production-plan-review.html)。模板需要操作者填入实际数据，不是自动渲染器。简单任务可在同一页逐步更新，复杂批次可分方案页、资产页和审片页，但应保留一个能找到当前版本的总入口。

## 2. 各阶段必须拿得出的成果

| 阶段 | 实际成果 | 不能省略的判断 |
| --- | --- | --- |
| 读原片 | 来源、可打开参考、实际查看范围、剧情因果 | 首镜谁已在场、接触如何发生、反转/揭示为何成立、结尾是否完整 |
| 设计版本 | 稳定编号、A/B源职责到目标身份/状态/声音的映射 | 角色互换改变剧情职责，声音仍归各自身份；无角色任务标明不适用 |
| 替换方案 | 每版原→新元素表及 HTML 方案 | 按本次允许的范围设计各版差异，保留动作所需结构与空间 |
| 准备资产 | 实际图、职责、检查结论和请求绑定 | 按本地要求核对完整开场图，明确身份、场景与状态的分工 |
| 提交 | 正式正文、实际附件、参数/费用预检、任务号与回执 | 方案中的新元素确实进入请求；未提交就写未提交 |
| 审片 | 可直接播放的真实结果与参考、逐版检查和偏差 | 故事/动作、元素替换、声音/口型均有实际检查范围 |
| 修订 | 用户原话、改动和保留范围、修订号、真实新结果 | 只推进所要求的改动，保留已接受部分及旧版 |
| 文件交付 | 当前选定文件、原生/拼接/补音来源、可打开文件入口 | 不用候选浏览推定采用；不把改名、复制当新增制作 |

## 3. 元素替换要形成闭环

场景和元素替换偏好已启用时，默认主动设计本版背景、主要道具及可换装饰，而不等用户逐个提醒。用户明确保留的内容优先。角色核准身份、标志衣装不作为随意可换装饰。不要为了差异破坏原片的机制：新桌子要有足够的接触空间，新柜子要能遮挡后再揭示，新工具要能完成目标动作。

每版保留版本编号、要求、替换与保留功能、落实资产及实际请求槽位、成片检查点和结果。需要换景时核对本版真实空间及元素。物体改变时连带检查工具、残留、痕迹和角色反应。

用户指定的每一项变更贯穿五处：**方案 → 资产 → 实际上传附件/槽位 → 最终正文与参数 → 结果核对及当前审片页/文件。** 不只改方案标题。已有合格资产可复用，最终以实际请求为准。

## 4. 提示词和资产的职责

原片参考控制动作顺序、节奏、接触与镜头逻辑；身份图控制外形、服装、材质与比例；场景图控制空间与元素；状态图只在对应事件后生效。清楚标出各素材标签和实际索引，避免“左边的人”“图一角色”等指代在不同版本中串位。

直接写指令，如“严格参考原视频的动作与因果，自然安排动作衔接”；不写“让模型……”。不把每段秒数掐死，不扩写与原片相冲突的剧情；关键开场、接触、状态触发和完整结尾仍需明确。纯图重建不挂旧视频，不引用不存在的“视频1”。

方案页展示需要核对的资产缩略图或可打开入口，以及待生成/已生成未查看/已检查/不可用等真实状态。计划生成的图不能冒充已可用。资产图不自动成为字面首帧，除非确实按该模式提交。

## 5. HTML 方案与审片的最低内容

方案页包含原片机制、稳定版本编号、职责与声音、各版替换表、用户指定项、必要资产及待办。确认制作后页中继续保存真实提交状态、精确模型版本/价档、时长/分辨率/画幅/音频等实际参数、单项和整批预计消耗与未知项、授权范围和回执入口。私人鉴权信息不可入页。

结果页每版必须能看清：

- 原片与当前生成文件的真实播放器或可打开入口；尚无文件时用空占位，不挂演示视频。
- 当前 revision、角色职责、场景变化、原任务号、真实状态及输出文件；状态从所选真实记录填写。
- 来源是平台原生、拼接、补音或其他本地编辑，保留对应原生版本。
- 技术检查、抽帧、完整动态观看、听审与口型的各自结论及范围；没做的保持未检查。
- 首镜在场、角色身份/比例/状态、关键接触、完整结尾和本版替换落实情况，及已知偏差。
- 用户反馈、保留项、修订动作、旧版入口与当前交付入口。

长片已分前后段时，页首先放完整拼接版，再给前/后段和旧版入口。播放器不自动播放，多条避免同时出声。中文路径与相对媒体链接必须能解析；桌面文件复制后重新核对路径和指纹。页面不显示账号凭据或过量技术细节，详细请求可折叠或链接本地记录。

平台成功、文件可解码、用户接受和操作者完整听审是不同事实。用户接受具体版本但操作者未听审时，两条依据可以并存，不能补造通过。模板里的“未检查”也不能在完成后不加核对地机械沿用；当前页应反映当前所选文件的真实记录。

## 6. 反馈与版本维护

把用户原话转成可检查的改动。例如“开柜前里面已经很多小角色”要求遮挡揭示已有内容；不能改成开门后魔法生成。反馈表写清受影响版本、改什么、保留什么、资产/正文/实际附件如何落实，以及是否已有付费修订授权。

先判断问题在参考理解、角色职责、资产、实际绑定、正文、参数、生成结果还是后期。按最小有效范围修订：能剪辑补声的不必自行整片付费重做；需重做时只在授权范围提交。旧文件不覆盖；当前入口指向新选定 revision，旧版明确标注。

## 7. 新机器和新任务的接续

只携带方法时无需恢复旧库存。至少携带本页、执行流程、模板、私人偏好和核准资产清单；制作前实际检查工具、鉴权、模型与价格。旧下载包不会自动获得新文档。

项目根 README 说明流程；标准名称 **AGENTS.md** 写接手者约定；技能入口链接本页。AGENTS 的适用范围取决于工作目录和工具加载规则，安装技能不能保证任意目录的根文档都会被读到。已有聊天应显式要求读取更新；新机以正确工作目录进入，并完成接手自测。文档不能保证生成随机性下的画面完全一致。

通用方法与空模板可以进入代码库；用户素材、声音、路径、请求回执、成片和私人交接包留在本地。记录文档修改不等于上传 GitHub、发布新版或获得媒体生成授权。
