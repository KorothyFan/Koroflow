# 多版本复刻委托与提示词结构

在同一参考视频生成多个角色版本，或要求指定声音、背景改动、核心笑点和并行制作时读取本页。用户提供的同行提示词是委托结构的参考，不代表已观看原视频、已拥有素材或已验证生成效果。把其中具体角色、模型、画风与并发数当作该次参数，不升级成所有任务的默认规则。

## 把委托整理成制作约束

按用户给出的信息提取以下内容，已明确的内容不重复询问：

| 项目 | 应记录的内容 |
| --- | --- |
| 原片与输出 | 可访问的原片；独立成片数量、画幅/时长要求；版本 id |
| 角色识别 | 原角色在某个源时间点的左右位置、帽子或其他特征，绑定稳定角色 id |
| 每版角色映射 | 每个原角色对应的新角色，使用的身份参考与明确的外形要求 |
| 视觉 | 真人、Q 萌或其他风格；原片中要继承的光线、材质、摄影/动画语言 |
| 保留内容 | 剧情、动作事件、镜头设计、表情变化、剪辑与声音关系 |
| 核心事件 | 笑点/反转依赖的变化及其时机、前后状态与其他角色的反应 |
| 允许变化 | 背景、角色、台词或声音哪些可以改，不能把一个允许项扩展到其他部分 |
| 声音与文字 | 逐句说话角色、实际要念的文本、音色/表演、音频参考、字幕是否同文 |
| 执行 | 主模型、备选模型的条件与可用性、并发请求上限、已接受预算与重试范围 |

“从左到右 A/B/C”只能建立初始映射；镜头反打或角色移动后沿用同一角色 id，不重新按当前位置命名。“戴帽子的角色”也不能在替换后因目标角色没有帽子而变成另一人。未知角色名或别名不足以确定准确形象时优先找用户明确关联的素材，关键身份仍不清楚才澄清，不猜原作或外形。

## 连续性允许有剧情变化

将角色稳定特征与剧情变化分别记录。例如“中间人物发型变化是笑点”时，发型不是全片固定属性：按原片证据记录变化前后状态、变化发生时机、镜头揭示和其他人的反应。保持该版本的角色身份和故事因果，不能用统一发型参考把笑点抹掉。

换背景时保留承载动作的空间关系：座位顺序、距离、视线、道具位置、接触与运动范围。改变装饰、地点或色调不自动允许改变构图和故事。真人与 Q 萌是角色表现要求；若与“画风保持原片一致”发生实际冲突，说明需要保留的摄影/动画风格与需要转换的角色材质，必要时解决视觉目标。

“表情生动夸张、动作丝滑”应落到逐镜可见的反应、幅度、停顿与接续，不额外创造剧情。具体事件必须从原片确认，不能仅凭委托中的一句笑点描述编造完整动作链。

## 台词与声音按说话回合绑定

建立逐句表：源时间/回合 id → 角色 id → 目标台词 → 字幕文字 → 音频参考用途 → 表演。明确音频用来参考音色、表达节奏，还是直接作为最终音轨；文件名或一句音效并不能证明它支持任意句子配音。

如同一委托同时要求角色标志性口头禅和朗读英文字幕，先判断它们是否指向不同说话回合。若同一回合存在两种互斥台词，记录冲突并向用户澄清，不能默默把全部对白改成口头禅，也不能把对白与字幕随意拼接。只对实际需要的冲突提问，其他分析继续。

提交前核实参考音频在当前机器存在、可播放且正确对应角色；他人机器上的路径不自动成为本机资产。当前模型必须支持该参考的预期用途；没有可靠音色控制时选择已可用的独立语音生成/原音轨复用路径并说明。采用的台词进入 Source，表格引用回合 id 而不是维持另一份正式全文。

## 独立版本与并行请求

共享只读原片分析，各版本分别保存 Brief、Treatment、Source、Runs、Results、Runtime 数据和最终输出，角色映射与声音绑定不跨版本混用。独立成片数量不等于模型请求并发数：一个版本可能需要多个镜头请求，参考素材生成与下游视频还存在依赖。

把“并行 2/3 条任务”解释为待落实的调度要求，并核对究竟指独立成片、生成请求还是另开聊天。不能据此擅自创建新聊天，不能把第三条任务变成第三支成片。能明确推断为生成请求上限时按此记录；执行前检查当前 Runtime/工具是否能设置、账号限流和任务依赖，再选择受支持的并发方式。没有实测或配置证据时不宣称已经并行执行。预算按各版、各镜头及已接受重试累计，不能把“每版预算”误作总预算。

## 模型备选与失败恢复

可记录用户为该任务指定的 Seedance 2.5 主模型与 Wan3 等备选偏好。当前集成 Provider 不包含 Wan3，先查询海艺实际模型及其图片/视频/音频参考、时长和费用要求；若可用，可通过原海艺技能执行后导入 Hypit，不能仅替换模型名称沿用 Seedance 参数。不存在或未配置时报告具体缺口，不声称自动切换已经实现。

被拒、超时、限流和服务错误分别按实际错误证据处理，不把所有失败归因于版权。先确定原任务状态与是否已计费，再按已有授权选择修正输入、可用备选或停止该请求。遵守服务返回的限制；不以规避服务限制为重试目标。用户给出的备选规则不代表无限重试预算。

## 把委托变成各模型的具体请求

长委托保存为项目约束，不把全部版本、角色和声音要求原样塞进每次模型调用。每个请求只接收本版本、本镜头相关的角色参考、动作片段、目标台词和保留/改动指令；身份、构图、动作、声音参考明确各自用途。检查 plan 后提交已授权部分。

验收围绕硬要求：版本间没有角色串用，核心变化与反应时机成立，背景改动不破坏动作，台词/字幕/声音角色一致，表情与动作完整接续。成功素材显式复用，只修复受影响部分。文字结构整理与离线验证不能证明两条参考片的真实复刻效果。
